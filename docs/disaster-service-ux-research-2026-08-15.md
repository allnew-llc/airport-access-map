# 行政災害サービス UX/UI 調査と反映記録

- 調査日: 2026-08-15
- 対象: NARITA ACCESS NOW（成田空港アクセス障害ガイド）
- 目的: 海外旅行者が災害時に「現在の交通」「代替手段」「次の行動」を短時間で判断できる初期画面へ改善する

## 調査対象

| サービス / 指針 | 確認した設計 | 本システムへの示唆 |
|---|---|---|
| [東京都防災ホームページ](https://www.bousai.metro.tokyo.lg.jp/) | 現在の避難情報の有無を明示、多言語・やさしい日本語、公式行動情報への導線 | 「異常情報がない」ことも状態として表示し、言語切替と支援導線を初期画面から利用可能にする |
| [東京都防災マップ](https://map.bosai.metro.tokyo.lg.jp/ja.html?p=evacuation%2Fshelter) | 情報時点、地図と施設一覧、自治体・住所・施設検索、レイヤー、現在地、経路検索 | 地図と交通一覧を別々に閲覧させず、一覧から該当路線を地図へフォーカスできるようにする |
| [デジタル庁 防災分野](https://www.digital.go.jp/policies/disaster_prevention) | 迅速な状況把握、的確な意思決定、適切な行動、個々の状況に応じた支援 | データ表示を目的にせず、現在フェーズと旅行者の次の行動を同時に示す |
| [防災DXサービスマップ](https://bosai-dx.jp/) | 平時・切迫時・応急時・復旧復興時の4フェーズでサービスを整理 | 過去再生を単なる時刻表示にせず、切迫・応急・復旧の意味と行動を表示する |
| [DADS 緊急時バナー](https://design.digital.go.jp/dads/components/emergency-banner/) | 生命・身体・財産に関わる緊急情報だけを最上部に固定し、具体的な見出し、時刻、短い説明、1つの行動導線を示す | 赤い緊急バナーは検証済みの運転見合わせ・通行止めがある時だけ出し、通常の注意情報と分離する |
| [DADS ノティフィケーションバナー](https://design.digital.go.jp/dads/components/notification-banner/) | 通常の注意と緊急警告を意味・色・優先度で分離 | 注意情報は既存のサマリーパネルに残し、常時赤色にしない |

## 採用した設計原則

1. **状態を先に示す**
   現在フェーズと、「確認済みの交通手段数 / 要確認数」を交通サマリーの見出し内に表示する。

2. **緊急情報を希少に保つ**
   公式一次情報として扱えるデータに「見合わせ・通行止め」が存在する場合だけ、ページ最上部に緊急バナーを出す。確認根拠が不足する情報を緊急バナーへ昇格させない。

3. **一覧と地図を一つの操作にする**
   JR・京成・北総・道路の行を押すと、実際の収録経路に合わせて地図表示範囲を変更する。公式情報への外部リンクは別の44px以上の操作対象として残す。

4. **災害の時間変化を行動に翻訳する**
   過去再生では「切迫時」「応急時」「復旧時」を表示し、それぞれ「代替ルート確保」「移動停止・空港滞留への対応」「路線別の再開確認」へ結び付ける。

5. **多言語でも情報構造を変えない**
   日本語・英語・簡体字・繁体字・韓国語の全言語で、緊急性、フェーズ、確認範囲、地図操作の意味を揃える。

## 今回あえて採用しなかったもの

- 行政サイトの大規模なグローバルナビゲーション、広報カルーセル、SNS埋め込み
- 全災害種別・全自治体を同じ画面に並べる構成
- 閉じられる緊急バナー（未読のまま消えるため）
- 未確認を「平常」と見なす自動補完
- 地図と同じ交通一覧を別ページに重複配置すること

これらは、成田空港への移動判断という単一目的を弱め、緊急時の探索量を増やすため採用しない。

## 実装受入条件

- ライブ表示で重大事象がなければ、緊急バナーは表示しない
- 検証可能な重大事象があれば、最上部に見出し・更新時刻・説明・情報源への単一リンクを表示する
- 交通サマリーに現在フェーズと確認範囲が表示される
- 交通行の本体は地図へフォーカスし、右端の外部リンクは公式情報を開く
- すべての操作対象はキーボード操作可能で、主要操作は44px以上を確保する
- 5言語で追加項目が欠落しない
- 390px幅で横スクロールを発生させない
