# モバイル・ファーストビュー設計（390 × 844px）

## 目的

成田空港に到着した旅行者、または成田空港へ向かう旅行者が、最初の1画面で次の3点を把握できるようにする。

1. 地図：空港と主要交通ルートの位置、重大・注意・正常の状態
2. 交通サマリー：JR、京成、北総、空港バス、道路
3. 次の行動：空港から出たい、空港へ向かう、移動できないときの情報

実寸ワイヤーフレームは [`wireframes/mobile-first-screen-390x844.svg`](./wireframes/mobile-first-screen-390x844.svg) を正とする。

## 高さ配分

| 領域 | ワイヤーフレーム上の範囲 | 高さ | 役割 |
|---|---:|---:|---|
| ヘッダー | 0–72px | 72px | サービス名、言語、更新状態 |
| 地図 | 76–344px | 268px | 空港・実ルート・事象の空間把握 |
| 交通サマリー | 352–650px | 298px | 5カテゴリの状態と公式情報導線 |
| 次の行動 | 658–830px | 172px | 旅行者の状況別3アクション |
| 画面下端余白 | 830–844px | 14px | 844px境界内に収める安全余白 |

実装では文字の実レンダリング差を吸収するため、ヘッダー88px、地図250px、交通行44px、行動ボタン64pxを上限基準とする。

## モバイルで後段へ送る情報

- 最重要事象の詳細
- 路線別の詳細状態
- 情報源一覧
- 旅行者別の詳細ガイド
- 自治体支援・避難先

これらは削除せず、最初の判断後にスクロールして確認できる位置へ置く。

## 受け入れ条件

- CSS viewport が390 × 844pxのとき、地図、交通サマリー5行、3つの次行動ボタンがすべて画面内に入る。
- `document.documentElement.scrollWidth === 390` で横スクロールがない。
- 地図、交通行、行動リンクの操作対象は44px以上とする。
- 交通状態は「正常」「遅延・規制」「見合わせ・通行止め」の3種類に限定し、取得状態を交通状態として表示しない。
- 交通状態を表示できないカテゴリには、状態バッジを付けず公式情報へのリンクを表示する。
- 「移動できないとき」は待機場所・公式窓口などの情報案内であり、救助要請や有人サポートと誤認させる `HELP` 表示や赤い緊急配色を使用しない。
- 5言語でレイアウトが破綻しない。
