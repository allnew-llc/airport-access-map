# モバイル表示の設計原則（390 × 844px）

## 目的

空港に到着した旅行者、空港へ向かう旅行者、空港に滞在する旅行者が、スマートフォンで次の3点を一続きに確認できるようにする。

1. 地図：空港と主要交通ルートの位置、重大・注意・正常の状態
2. 交通サマリー：鉄道または接続交通、空港バス、道路
3. 移動方向：空港から移動、空港へ移動、空港に滞在

## 情報の順序

1. 空港、言語、表示する時点を選ぶ。
2. 地図上で交通・気象の全体像を確認する。
3. 移動方向を選ぶ。
4. 交通機関別の状態、区間、理由、代替候補を確認する。
5. 必要に応じて公式情報、空港内施設、自治体支援を開く。

## モバイルで後段へ送る情報

- 最重要事象の詳細
- 路線別の詳細状態
- 情報源一覧
- 自治体支援・避難先

これらは削除せず、最初の判断後にスクロールして確認できる位置へ置く。

## 受け入れ条件

- CSS viewport が390 × 844pxのとき、地図と3つの移動方向が横方向にはみ出さない。
- `document.documentElement.scrollWidth === 390` で横スクロールがない。
- 地図、交通行、行動リンクの操作対象は44px以上とする。
- 交通状態は「正常」「遅延・規制」「見合わせ・通行止め」の3種類に限定し、取得状態を交通状態として表示しない。
- 交通状態を表示できないカテゴリには、状態バッジを付けず公式情報へのリンクを表示する。
- 「空港に滞在」は待機場所・公式窓口などの情報案内であり、救助要請や有人サポートと誤認させる表現を使用しない。
- 5言語でレイアウトが破綻しない。
