# Airport Access Map：プロジェクト概要

## 公式情報が分かれていることで起きる問題

空港で交通障害や大雨が発生すると、旅行者は鉄道会社、バス会社、道路管理者、気象機関、空港、自治体のサイトを順番に確認する必要があります。土地勘や日本語の読解力が十分でない利用者ほど確認に時間がかかり、空港スタッフへの問い合わせも増えます。

Airport Access Mapは、これらの情報を空港単位で整理し、地図、交通サマリー、利用目的別の詳細を同じ画面で確認するためのOSSです。

## デモで確認できること

1. 空港名または3レターコードで、国内33空港から確認対象を選びます。
2. 鉄道、空港バス、道路、気象を地図と一覧で確認します。
3. 「空港から移動」「空港へ移動」「空港に滞在」を選ぶと、その目的に必要な情報だけを開きます。
4. 交通障害時の架空シナリオでは、状態変化、対象区間、理由、代替候補の見せ方を確認できます。
5. 空港に滞在する場合は、Wi-Fi・充電、休憩・宿泊、自治体支援、旅行者向け窓口を確認できます。

[AllNew.workでデモを開く](https://allnew.work/demo/airport-access/)

## 現在の実装範囲

- 33空港
- 5言語：日本語、英語、簡体字中国語、繁体字中国語、韓国語
- MapLibre GL JSと国土地理院タイル
- OpenStreetMap由来の静的な参考経路
- 1週間分の架空サンプル履歴
- GitHub Pagesで配信できる静的構成
- 公式リンクのallowlistと壊れたデータを止めるAndon Gate

## 公開デモが実データを使わない理由

交通事業者の公開ページを閲覧できることと、その本文や状態を別サイトで継続的に再配信できることは同じではありません。公開リポジトリには、未許諾の運行情報、取得済み本文、実履歴を収録していません。

実データを接続する場合は、データセットごとに次を確認します。

- 明示ライセンスまたは書面許諾
- 取得可能な項目、更新間隔、キャッシュ期間
- 翻訳と派生表示の可否
- 情報が古い、空、不正な場合の表示停止条件
- 緊急時の運用責任者と公式情報への導線

## 導入を検討するときの判断材料

このOSSがそのまま提供するのは、情報統合のUI、空港追加の構造、架空データ、品質ゲートです。実サービス化には、対象地域のデータ利用条件、運用体制、監視、アクセシビリティ検証を追加してください。

向いている用途：

- 空港や自治体による多言語案内のプロトタイプ
- 交通情報を一画面へ統合するUX検証
- 静的配信とフェイルセーフの技術検証
- 新しい空港を小さな追加コストで展開する実証

このまま使用すべきでない用途：

- 現在の運行可否を保証するサービス
- 救助、避難指示、経路案内を代行するシステム
- 許諾のない交通情報を自動取得・再掲載する運用

## 技術構成

```text
架空サンプル / 許諾済みデータ候補
              │
              ▼
        validation gates
              │
      BLOCK ──┴── PASS
        │            │
  直前正常版を維持   静的GeoJSONを生成
                     │
                     ▼
             Vite + MapLibre GL JS
                     │
                     ▼
               Static hosting
```

ブラウザが参照するのは静的ファイルです。交通データの取得処理と、旅行者が開く画面を分離することで、アクセス集中時に外部APIを直接圧迫しない構成にしています。
